Workflow in one paragraph

Open Vigil → dismiss the intro card → pick a scenario (header dropdown or a dashboard card) → the real engine scores it → a case opens only if score ≥ 60 (Account takeover, Card-testing ring); otherwise you get a read-only transaction-result page (Normal, Suspicious). Inside a case: 1 review the transaction → 2 check the risk signals → 3 read the score, the “Why this score?” breakdown and the recommendation → 4 (optionally run the AI investigation) pick an action → Confirm decision & close case → “✓ Case resolved” → Reset demo for the next run.

The 12 clicks for the live demo

  1. Open http://localhost:8000
  2. Got it — start the demo
  3. Normal payment card → 0 · LOW · Allow, no case — “it doesn’t cry wolf”
  4. ← Back to dashboard
  5. Suspicious payment card → ~36 · MEDIUM · Monitor, no case — “noted, not escalated”
  6. ← Back to dashboard
  7. Account takeover card → ~95 · CRITICAL, a case opens
  8. Read section 2 aloud; expand one warning row
  9. Section 3: point at “Why this score?” and VIGIL RECOMMENDS — BLOCK TRANSACTION
  10. (optional) Run AI investigation — skip if slow or it shows “engine-only”; it’s optional
  11. Section 4: Block Transaction → Confirm decision & close case → “✓ Case resolved”
  12. Reset demo
Only 60 seconds? Do steps 1, 2, 7, 9, 11, 12.

The three answers, verbatim

“Where did this transaction come from?” It’s synthetic data my backend generated — not typed by me, not from an external feed. Clicking Run scenario calls POST /api/simulate/scenario → inject_scenario() in backend/seed.py, which runs the scenario template (for Account takeover: _account_takeover() on the fixed demo customer CUST-1002). That function scripts the attack — a normal payment 35 minutes earlier in Pune, then three failed OTPs, then a large payment from a brand-new device in Kolkata (the farthest seeded city from Pune), plus two other accounts using that same device. Every row is inserted into the SQLite transactions / auth_events tables, scored by the engine, and the screen reads it back via GET /api/cases/{id}. The customer baseline it is compared against comes from seed() — random.Random(42), 90 days of synthetic history.
“How did Vigil calculate this risk score?” A deterministic formula in backend/risk/engine.py — no AI, no ML. Six signals each compare the payment to this customer’s own history and produce a 0–1 severity with a fixed weight: failed attempts (0.85), new device (0.60), far location (0.50), large amount (0.80), plus velocity and time-of-day. They are combined with grouped noisy-OR — p = 1 − Π(1 − group) — giving a base of about 96. Then two hard rules fire: impossible travel (1,574 km in 35 min ⇒ ~2,700 km/h, floor 85) and shared device (floor 75). Final score = max(base, highest floor) = 96. 96 ≥ 82 → CRITICAL; CRITICAL + a hard rule → the recommended action is Block. The on-screen “Why this score?” panel shows the exact per-signal points. Same database state → same number every time.
“What does the AI (Gemini) do in Vigil?” Only when the analyst clicks Run AI investigation. Gemini (gemini-3.6-flash) reads the case through five read-only tools and writes a plain-language summary, per-claim findings, and a second opinion (agree or dissent). Every number it states is re-computed against the database (backend/agent/validator.py) and tagged VERIFIED / UNVERIFIED / REFUTED. It does not calculate the score — its output schema has no score field — and it cannot take any action. If it errors or hits quota, runner.investigate() catches it and runs a deterministic engine-only fallback with the same output shape, clearly badged. The score, the recommendation, and the analyst’s decision are unaffected by whether the AI ran.

Honest limits (say these if asked)

  • Not machine learning. The score is rules + statistics with hand-set weights. No trained model.
  • No payment gateway. “Block” writes a decision row + changes the case status + an audit entry. transactions.status never changes; nothing is really stopped.
  • Synthetic data. 12 generated customers, ~1,080 transactions, all local.
  • AI is optional and advisory. Free-tier Gemini is 20 requests/day; when it runs out, Vigil falls back to engine-only automatically.
